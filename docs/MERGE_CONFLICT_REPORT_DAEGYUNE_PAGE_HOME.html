이번 merge에서 잡은 기준

  • 기존 서비스 화면은 우리 쪽 흐름을 우선 유지했다.
  • 대균 브랜치의 신규 auth, profile, document, notification 화면은 가져왔다.
  • Prisma는 단일 파일이 아니라 schema.prisma + models/*.prisma 분리 구조를 채택했다.
  • 채용공고 importer와 crawler는 운영 로직이 더 큰 우리 버전을 유지했다.
  • soft delete 패턴은 대균 쪽 구조를 받아서 backend 조회 로직에 녹였다.
  • README, CONTRIBUTING, env 계약은 둘 중 하나를 버리기보다 합치는 쪽으로 정리했다.

최종 검증

  • corepack pnpm --filter @neet2work/frontend lint, test, build 통과
  • corepack pnpm --filter @neet2work/backend lint, test 통과

참고: backend build는 merge worktree의 Prisma generated client unlink 권한 문제 때문에 승인 경로로 다시 실행해 확인했다.

merge 후 추가 패치

  • 후보자 프로필, 문서, 문서 세트 라우트는 클라이언트 candidateKey 대신 Authorization 기준으로만 접근하게 바꿨다.
  • trust proxy는 고정값이 아니라 환경값을 해석하도록 바꿨고, HTTPS 강제는 REQUIRE_HTTPS=true일 때만 적용되게 정리했다.
  • draft-workflow validation의 control regex를 제거해 backend lint가 다시 통과하도록 고쳤다.
  • job.service와 server 테스트는 soft delete와 인증 가드가 반영된 현재 구현 기준으로 기대값을 맞췄다.
  • DocumentSetDetail.tsx는 프로필을 실제 수정했을 때만 저장하게 바꿔 전체 저장 직후 검증 에러가 나던 흐름을 잡았다.

지금 상태

  • 충돌 marker 제거만 끝난 상태가 아니라, 리뷰에서 지적된 인증/프록시/HTTPS/테스트 문제까지 같이 정리된 상태다.
  • Prisma split 구조와 soft delete 패턴은 유지하면서 우리 쪽 채용공고 운영 로직과 대균 브랜치의 신규 문서/계정 기능을 함께 살렸다.
  • 프론트 테스트는 62개, 백엔드 테스트는 187개가 현재 merge 브랜치 기준으로 통과했다.
  • 수동 브라우저 QA는 별도 기록하지 않았고, 이 문서의 검증 상태는 로컬 lint/test/build 기준이다.

핵심만 다시 보면

  • 기존 채용공고 경험과 crawler/importer는 우리 쪽을 살렸다.
  • 대균 브랜치의 신규 auth/profile/document/notification 기능은 받아들였다.
  • Prisma는 split 구조를 채택했고, soft delete 패턴도 같이 가져왔다.
  • merge 뒤에는 server.ts, 인증 라우트들, DocumentSetDetail.tsx, 테스트 파일들까지 추가 손질이 들어갔다.
